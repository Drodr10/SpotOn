# App Store and Play Console privacy declarations

Companion to `docs/privacy-policy.html`. Apple's **App Privacy** section and Google's
**Data safety** form ask the same questions in different words, and both are compared
against what the app actually does. A mismatch is a rejection, and a mismatch that gets
through is worse — it is a public statement that is not true.

Everything here was read off the schema, `frontend/package.json` and the permission calls
in `frontend/src/`, not from memory.

---

## The answer to "do you collect this" for every category

| Data type | Collected | Linked to identity | Used for tracking | Where it lives |
|---|---|---|---|---|
| Name | Yes | Yes | No | `profiles.full_name` |
| Email address | Yes | Yes | No | `profiles.email`, `auth.users` |
| Photos | Yes | Yes | No | `avatars` bucket, `listing_images` |
| Precise location | Yes | Yes | No | `listings.latitude/longitude` — the **spot's** location, not the user's |
| Coarse location | Used, not collected | — | No | Read on device to rank nearby listings; never sent to us |
| Payment info | No (Stripe collects) | — | No | Stripe. We hold only references. |
| Purchase history | Yes | Yes | No | `reservations` — times, price, fee, payout |
| Other financial info | Yes | Yes | No | `profiles.stripe_account_id`, `payouts_enabled` |
| Messages / other user content | Yes | Yes | No | `messages.content`, `conversations.last_message` |
| Device ID / push token | Yes | Yes | No | `profiles.expo_push_token` |
| Vehicle information | Yes | Yes | No | `vehicles` — make, model, colour, **full licence plate** |
| Contacts, browsing history, search history, health, ads data | No | — | — | Not collected in any form |
| Crash data / diagnostics / analytics | No | — | — | No analytics or crash SDK is installed |

**Tracking is "No" across the board.** There is no third-party analytics, advertising or
attribution SDK in `package.json`, so no App Tracking Transparency prompt is needed.

### Purposes to select
App Functionality for everything. Not Analytics, not Advertising, not Personalisation —
none of those are true here.

### Licence plate
Neither form has a "licence plate" category. Apple's closest fit is **Sensitive Info** or
**Other Data**; Play's is **Personal identifiers** under Personal info. Declare it rather
than letting it fall through a gap — it is the most identifying thing the app stores, and
the policy calls it out by name in §2.

## Google Play: the account-deletion URL

Play requires a URL where someone who has **uninstalled** the app can start a deletion
request. `docs/privacy-policy.html` §8 is that page, and it only works once the deletion
email address in it is real and monitored. Submit the hosted URL of that page.

Apple's requirement is different and already met: deletion must be reachable **inside**
the app (Profile → Delete my account, added in `db45523`).

## Two things to fix before submitting

Both are in the generated `frontend/ios/SpotOn/Info.plist`. That directory is gitignored
and regenerated by `npx expo prebuild`, so the fix belongs in `app.json` under
`expo.ios.infoPlist`, not in the generated file.

### 1. The app declares permissions it never uses

Expo's default config plugins wrote these in:

```
NSMicrophoneUsageDescription                      — the app never records audio
NSLocationAlwaysUsageDescription                  — only requestForegroundPermissionsAsync is called
NSLocationAlwaysAndWhenInUseUsageDescription      — same
```

Declaring background location invites Apple to ask why, and would force "Always" into the
privacy label for a capability the code does not use. `grep -rn
"requestForegroundPermissionsAsync\|requestBackgroundPermissionsAsync" frontend/src/`
returns foreground calls only, in three files.

### 2. The usage strings are the generic defaults

Every one currently reads `Allow $(PRODUCT_NAME) to access your <thing>`, which explains
nothing and is a common rejection reason under Guideline 5.1.1. Replace with the actual
reason, e.g.:

| Key | Suggested string |
|---|---|
| `NSLocationWhenInUseUsageDescription` | SpotOn uses your location to show parking spaces near you, and to place a spot you are listing. |
| `NSCameraUsageDescription` | SpotOn uses your camera to photograph a parking space you are listing. |
| `NSPhotoLibraryUsageDescription` | SpotOn uses your photos for your profile picture and your listing photos. |

Set them in `app.json`, drop the three unused keys, then re-run `npx expo prebuild` and
confirm with `grep -A1 UsageDescription frontend/ios/SpotOn/Info.plist`.
